# Murmur for iOS

SwiftUI app (bundle id `com.murmur.app`, min iOS 17) sitting on top of `crates/murmur-core`,
which reaches Swift as `MurmurCore.xcframework` through UniFFI.

## First build

Build the Rust core once before you open or build the project — Xcode resolves the
`MurmurCoreFFI` binary target before any script phase runs, so the framework has to exist
already:

```bash
scripts/build-core-mobile.sh ios      # from the repo root
```

After that the app target's **Build MurmurCore** pre-build phase re-runs the same script on
every build to keep the framework fresh. Because the framework is unpacked before that phase,
a change to `crates/murmur-core` lands in the build *after* the one that rebuilt it — build
twice, or run the script by hand, when you have just edited Rust.

## Build and test

```bash
cd apple && xcodegen generate && cd ..                       # after any project.yml change
xcodebuild -project apple/Murmur.xcodeproj -scheme Murmur \
  -destination 'platform=iOS Simulator,name=iPhone 17' test
```

`xcrun simctl list devices available | grep iPhone` lists the simulator names this Mac offers.

## Layout

| Path | What it is |
|---|---|
| `project.yml` | XcodeGen spec — **the source of truth**. Never hand-edit the pbxproj. |
| `Murmur.xcodeproj`, `Murmur/Info.plist` | Generated by `xcodegen generate`; both committed so a fresh clone builds without XcodeGen installed. |
| `Murmur/` | The app: `MurmurApp` (entry point), `HomeView`, asset catalogue. |
| `MurmurTests/` | Unit tests. They run on the simulator, so they exercise the real FFI. |
| `MurmurShared/` | Swift package. `MurmurCore` wraps the generated bindings + the xcframework; `MurmurShared` is the hand-written layer (`CoreClient`) the app imports. |
| `Frameworks/MurmurCore.xcframework` | Build output, gitignored. |
| `MurmurShared/Sources/MurmurCore/Generated/` | Generated UniFFI bindings, gitignored. |
